# tvc-policy-sidecar

A [Turnkey Verifiable Cloud (TVC)](https://docs.turnkey.com/features/verifiable-cloud/overview) app that integrates with Turnkey and extends Turnkey policies programmatically. 

It subscribes to Turnkey activity webhooks, verifies webhook signatures, checks activities against additional in-app policies, and submits an approval or rejection vote using its long-lived quorum key.

## Aptos parsing demo overview

This TVC app enables parsing an Aptos payload (currently unsupported natively within Turnkey), and only approves payloads to a specific recipient when the transfer amount plus maximum gas cost is at most 10 APT.

### End to end flow

```
End user / initiator
   |
   | submit ACTIVITY_TYPE_SIGN_RAW_PAYLOAD_V2
   | with Aptos transaction signing bytes
   v
TKMS
   |
   | authenticate + evaluate Turnkey policy
   | activity enters ACTIVITY_STATUS_CONSENSUS_NEEDED
   | send signed ACTIVITY_UPDATES webhook
   v
TVC app co-signer
   |
   | verify webhook signature, freshness, and organization
   | check activity eligibility
   | parse signing bytes + evaluate Aptos transfer policy
   | submit approve_activity or reject_activity
   | signed with the quorum-derived API key
   v
TKMS
   |
   | evaluate the vote against configured consensus
   | complete signing, reject, or continue awaiting approvals
   v
Activity result
```

An approval requires all of the following:

- An `ACTIVITY_TYPE_SIGN_RAW_PAYLOAD_V2` activity awaiting consensus.
- Standard single-sender Aptos Ed25519 signing bytes:
  `SHA3-256("APTOS::RawTransaction") || BCS(raw_transaction)`.
- Entry function `0x1::aptos_account::transfer`, no type arguments, and exactly
  the recipient and amount arguments.
- Recipient `0x0707070707070707070707070707070707070707070707070707070707070707`.
- Amount plus `max_gas_amount × gas_unit_price` is **at most 1,000,000,000 octas (10 APT)**. 

Malformed signing bytes and policy violations are rejected. Other activity types, completed activities,
batches, and noncanonical signers are ignored without a vote. An ignored activity may remain awaiting consensus.

### Endpoints and configuration

| Endpoint | Purpose |
| --- | --- |
| `GET /health` | Liveness: `{"status":"healthy"}`. |
| `GET /turnkey/api_public_key` | Compressed P-256 public key and `API_KEY_CURVE_P256`, to be registered as a service user in Turnkey. |
| `POST /webhooks/turnkey/activity` | Signed Turnkey activity updates; verifies and votes. |
| `GET /metrics` | Prometheus HTTP metrics. |
| `GET /hello_world`, `GET /time` | Basic diagnostic endpoints. |

The webhook returns `204` after an accepted vote or intentional ignore, `401`
for authentication failures, `400`/`413` for malformed/oversized requests, and
`503` for retryable JWKS or Turnkey API failures (including upstream rate limits).
Terminal Turnkey vote failures return `400` and are not policy rejection votes.
Requests are limited to 1 MiB.

| CLI argument | Default / purpose |
| --- | --- |
| `--turnkey-organization-id` | Required; organization whose activities this app serves. |
| `--turnkey-api-base-url` | `https://api.turnkey.com`; used for votes and webhook JWKS. |
| `--host` | `127.0.0.1`; deploy with `0.0.0.0`. |
| `--port` | `44020`; use the same ingress and health-check ports. |
| `--quorum-file` | `/qos.quorum.key`; QOS-provided quorum key. |
| `--ephemeral-file` | `/qos.ephemeral.key`; QOS-provided boot key, validated at startup. |

## Deploy to TVC

### 1. Create a private quorum key and app

This walkthrough uses two hosted
operators and a 2-of-2 quorum-key share set. Their keys remain hosted by Turnkey;
this share threshold is separate from Turnkey activity consensus.

```sh
tvc login --api-base-url https://api.turnkey.com
tvc operator create --name policy-sidecar-operator-1 --wallet-name policy-sidecar-operators
# Save the returned wallet and operator IDs.
export WALLET_ID='<HOSTED_WALLET_ID>'
export OPERATOR_1_ID='<OPERATOR_1_ID>'

tvc operator create --name policy-sidecar-operator-2 \
  --wallet-id "$WALLET_ID" --account-path "m/5527107'/0'/1'"
export OPERATOR_2_ID='<OPERATOR_2_ID>'

tvc keys create-quorum-key --threshold 2 \
  --operator-ids "$OPERATOR_1_ID,$OPERATOR_2_ID"
# Save the returned quorum public key.
tvc app init --output app.json
```

Edit `app.json` with the returned values using the following shape. Replace all
placeholders; retain other compatible fields generated by your CLI.
**Replace the template's publicly known demo quorum key**: this app uses its
quorum signing key as a Turnkey credential. Do not use the known bootstrap key.

```json
{
  "name": "tvc-policy-sidecar",
  "quorumPublicKey": "<QUORUM_PUBLIC_KEY>",
  "enableEgress": true,
  "manifestSetParams": {
    "name": "policy-sidecar-manifests",
    "threshold": 1,
    "newOperators": [],
    "existingOperatorIds": ["<OPERATOR_1_ID>"]
  },
  "shareSetParams": {
    "name": "policy-sidecar-shares",
    "threshold": 2,
    "newOperators": [],
    "existingOperatorIds": ["<OPERATOR_1_ID>", "<OPERATOR_2_ID>"]
  },
  "dangerousEnableDebugModeDeployments": false
}
```

Egress is required to fetch webhook verification keys and submit Turnkey votes.
Without it, webhook handling fails. The manifest approver
controls which code runs; both share operators provision the quorum key.

```sh
tvc app create --config-file app.json
# Save the returned app ID.
tvc deploy init --output deploy.json
```

### 2. Configure, approve, and provision

Edit the generated `deploy.json`:

| Field | Value |
| --- | --- |
| `appId` | App ID returned above. |
| `qosVersion` | Supported QOS version from the generated template/current TVC release. |
| `pivotContainerImageUrl` | The full `IMAGE_URL` pinned by image manifest digest. |
| `pivotContainerEncryptedPullSecret` | Remove this field for a public image; replace the generated placeholder with a real encrypted pull secret for a private registry. |
| `pivotPath` | `/tvc_app` |
| `pivotArgs` | `["--host", "0.0.0.0", "--port", "44020", "--turnkey-organization-id", "<YOUR_ORG_ID>"]` |
| `expectedPivotDigest` | The hash of the binary inside the container. |
| `healthCheckType` | `TVC_HEALTH_CHECK_TYPE_HTTP` |
| `healthCheckPort`, `publicIngressPort` | `44020` |
| `dangerousDeployDebugMode` | `false` |

Then run
```sh
tvc deploy create --config-file deploy.json
export DEPLOYMENT_ID='<RETURNED_DEPLOYMENT_ID>'
tvc deploy approve --deploy-id "$DEPLOYMENT_ID" --operator-id "$OPERATOR_1_ID"

# Wait until attestation and manifest approvals can be verified.
tvc deploy provisioning-details --deploy-id "$DEPLOYMENT_ID"
# Once verification succeeds, provision both shares without skipping verification.
tvc deploy provision --deploy-id "$DEPLOYMENT_ID" --operator-id "$OPERATOR_1_ID"
tvc deploy provision --deploy-id "$DEPLOYMENT_ID" --operator-id "$OPERATOR_2_ID"
tvc deploy status --deploy-id "$DEPLOYMENT_ID"
```

Initialization may take a few minutes; retry provisioning-details after about
30 seconds if the attestation document is not available yet. Once the deployment
is LIVE, check its public URL:

```sh
export TVC_URL='https://app-<APP_UUID>.turnkey.cloud'
curl "$TVC_URL/health"
curl "$TVC_URL/turnkey/api_public_key"
```

A healthy process is ready for Turnkey registration; it does not yet prove the
organization's policies and webhook are wired correctly.

## Connect Turnkey consensus

In the organization passed through `--turnkey-organization-id`:

1. Create a dedicated API-only service user. Register the deployed endpoint's
   `publicKey` with its returned `curveType` (`API_KEY_CURVE_P256`). Do not
   generate an unrelated API key. Record the service user's ID.
2. The activity initiator must be a **different user**, with its own credential and a
   Turnkey-owned Ed25519 key/account with an Aptos address. Two credentials on
   the same user do not provide two independent approvals.
3. Add a consensus policy requiring both users. For a standalone private key,
   this example scopes the policy to that key:

```json
{
  "policyName": "Require TVC Aptos policy approval",
  "effect": "EFFECT_ALLOW",
  "condition": "activity.type == 'ACTIVITY_TYPE_SIGN_RAW_PAYLOAD_V2' && private_key.id == '<APTOS_PRIVATE_KEY_ID>'",
  "consensus": "approvers.any(user, user.id == '<INITIATOR_USER_ID>') && approvers.any(user, user.id == '<TVC_SERVICE_USER_ID>')"
}
```

See the [policy language](https://docs.turnkey.com/features/policies/language) for expanding this policy. This app currently is not written to be a part of root quorum, though it can be.

4. Create a [webhook endpoint](https://docs.turnkey.com/features/webhooks/overview)
   at `https://app-<APP_UUID>.turnkey.cloud/webhooks/turnkey/activity` and subscribe
   it to `ACTIVITY_UPDATES` in the same organization.
5. Submit a supported raw-signing request using the initiator's credential.
   Confirm it needs consensus, then receives the TVC vote and completes or is
   rejected. An API submission failure is not a TVC policy rejection.

The initial request counts as the initiator's approval. The app authenticates the
raw webhook body following Turnkey's [signature contract](https://docs.turnkey.com/features/webhooks/verify-signatures),
checks organization binding, and votes using the supplied activity fingerprint.

## Limits and extension points

- This is offline validation of one Aptos transaction shape, not a general
  signing policy. Digest-only payloads, signed envelopes, scripts, multisig,
  multi-agent/fee-payer messages, and other entry functions are unsupported.
- Chain ID, expiration, balances, and account rotation/state are not checked.
  The demo assumes unrotated Ed25519 accounts. Address shape alone does not
  establish a chain or curve. The 10 APT limit is per transaction, not cumulative.
- Duplicate handling is bounded, in memory, and per replica. It does not
  survive restarts or coordinate replicas. Votes complete before webhook success;
  there is no background queue.
- The quorum-derived public key stays stable while the quorum key is retained.
  Replacing that key requires updating the registered Turnkey credential.
- This app returns no application proof. The ephemeral key is loaded for QOS
  startup compatibility; fetching the API public key alone is not attestation
  verification.

To extend, see [`aptos_policy.rs`](crates/policy-sidecar/src/aptos_policy.rs) for
the existing policies.
